# What changed in the code, and which changes alter experimental behaviour

The 2024 code is preserved verbatim under `archive/2024-original/`. The replacements under
`src/biodiv/`, `scripts/` and `notebooks/` were written in October 2026. Every item below was
verified by reading the code and, where marked *(verified by execution)*, by running a check on
CPU with a randomly initialised model (no datasets or pretrained weights were used).

**Historical results keep their original provenance.** Nothing in `results/` was produced by
the new code. A run of the new code is a *different* experiment and must be reported as such.

Behaviour-changing fixes are marked **[changes results]**; the others only affect robustness,
portability or clarity.

## Hiera fine-tuning (`inat2019-mfinal-300epochs.py`, `inat2021-mfinal-300.py` -> `src/biodiv/train.py` and friends)

| # | Finding in the 2024 scripts | Status | What the new code does | Effect |
|---|---|---|---|---|
| T1 | Validation used `data_transform`, i.e. `RandomHorizontalFlip` + `RandAugment(9, 1)`, in both scripts (`INatDataset(..., transform=data_transform)` for val in 2019; `ImageFolder(val_dir, transform=data_transform)` in 2021). | Confirmed | `transforms.build_eval_transform` (resize, tensor, normalise only) for validation; `build_train_transform` for training. Tested in `tests/test_transforms.py`. | **[changes results]** Historical validation accuracies were measured on randomly augmented validation images; a rerun will measure clean images. |
| T2 | The 2019 `INatDataset.__init__` set `self.transform = data_transform`, ignoring the `transform` argument. Also `list(self.image_dict.keys())[idx]` rebuilt a 265k-element list on every item. | Confirmed | `inat.INatDataset` stores and applies the transform it is given; records are a list indexed directly. Tested in `tests/test_inat.py`. | No numeric effect in 2024 (the same global was passed anyway); large speed-up. |
| T3 | Class mappings: 2019 used raw `category_id` from the JSON (contiguous 0-1009 in practice) with `num_classes = len(categories.json)`; 2021 used `ImageFolder` class indices (sorted folder names, consistent between train and val only because every folder exists in both). Neither checked train/val agreement. | Confirmed; no mismatch in the actual data | `inat.CategoryMap` maps ids to indices explicitly (sorted ids, works for shuffled / non-contiguous ids), `assert_same` compares train and val maps, both years go through the JSON annotations. Tested with shuffled non-contiguous ids. | No numeric effect for the real datasets; prevents silent label mismatches. |
| T4 | `BottleNeck` / `DropPath` classes were defined and swapped in with `for name, module in model.named_children(): if isinstance(module, BottleNeck)`. Hiera has children `patch_embed, unroll, reroll, blocks, norm, head`; none is a `BottleNeck`. The loop did nothing. | Confirmed *(verified by execution: 0 matches, 0 DropPath modules with p>0)* | Dead code removed. `hiera_model.build_hiera` passes `drop_path_rate` to Hiera's own constructor, which installs per-block `DropPath` with rates increasing linearly to the requested value (0.0091 ... 0.1 for 12 blocks). Tested in `tests/test_hiera_model.py`. | **[changes results]** Historical runs had no stochastic depth even though 0.1 was reported; the configs now apply 0.1. Set `drop_path_rate: 0.0` to match the historical behaviour. |
| T5 | `mixup_alpha = 0.8`, `cutmix_alpha = 1.0` were assigned but `v2.MixUp(num_classes=...)` / `v2.CutMix(num_classes=...)` were built without them; torchvision defaults both to 1.0. | Confirmed | Alphas are passed from the config (`mixup_alpha`, `cutmix_alpha`). | **[changes results]** Historical MixUp used alpha 1.0; the configs now use the intended 0.8. Set `mixup_alpha: 1.0` to match history. |
| T6 | Layer-wise LR: a loop parsed parameter names (`name.split('.')[1]`) and multiplied `lr` by 0.65 whenever that token changed, starting from 3e-3; every parameter got its own group, so AdamW's `lr=2e-3` was never used. Effective rates *(verified by replaying the loop on hiera_tiny_224)*: head 1.95e-3, final norm 1.27e-3, blocks 11 -> 0: 8.24e-4, 5.36e-4, 3.48e-4, 2.26e-4, 1.47e-4, 9.56e-5, 6.21e-5, 4.04e-5, 2.63e-5, 1.71e-5, 1.11e-5, 7.21e-6; patch and position embeddings 4.69e-6. | Confirmed | `optim.layerwise_lr_param_groups` uses the standard layer-id scheme: head and norm `base_lr` (2e-3), block i `base_lr * 0.65^(12-i)` (1.3e-3 ... 1.1e-5), embeddings `base_lr * 0.65^13` (7.2e-6). Tested in `tests/test_optim.py`. | **[changes results]** Each block's rate is 1.5-2x the historical one and the head gets 2e-3 instead of 1.95e-3. The intent stated in the W&B report ("learning rate 2e-3, layer-wise decay 0.65") is now what runs. |
| T7 | Schedule: `ConstantLR(factor=0.1, total_iters=5)` then `CosineAnnealingLR(T_max=300)` via `SequentialLR(milestones=[5])`. The first 5 epochs ran at a *constant* 10% of each group's rate (not a warmup ramp), and the cosine was defined over 300 epochs but only stepped 295 times. | Confirmed | `optim.build_scheduler`: linear warmup over `warmup_epochs` to the full rate, then cosine to zero over the remaining epochs. Tested. | **[changes results]** Different first-5-epoch rates and a cosine that reaches zero at the last epoch (the historical one would have ended at 0.07% of base). |
| T8 | Validation loss was computed as `CrossEntropyLoss(model(inputs), labels)` with the model in eval mode. Hiera's `Head.forward` applies `softmax` when `not self.training`, so the loss saw probabilities, not logits. | Confirmed *(verified by execution: CE on eval outputs = ln(num_classes) to 1e-5)* | `build_hiera(..., logits_in_eval=True)` replaces `head.act_func` with the identity, so eval outputs are logits; `train.evaluate` reports a meaningful loss plus top-1/top-5. Tested. | **[changes results for the loss only]** Historical `val_loss` values (~6.5 and ~8.9) are meaningless. Accuracy is unaffected because softmax preserves the argmax. |
| T9 | Checkpoints: directory built from `$USER` and `$SLURM_JOB_ID` (crashes outside SLURM), file names differ between scripts (`checkpoint19_{n}.pth` vs `checkpoint_epoch_{n}.pth`), the resume branch was commented out, final weights were written to the current directory. | Confirmed | `checkpoint.save_checkpoint` / `load_checkpoint` / `find_latest` with an explicit directory under `BIODIV_OUTPUT_DIR`, `epoch_{n:04d}.pt` plus `last.pt`, `resume: auto`. Resume restores model, optimiser, scheduler and scaler state. Tested in `tests/test_checkpoint.py` and end-to-end in `tests/test_train_smoke.py`. | No numeric effect. |
| T10 | `from RandAugment import RandAugment` imported a third-party package that was never used (torchvision's `RandAugment` was used instead). | Confirmed | Removed. | None. |
| T11 | `wandb.init(...)` ran unconditionally, so the script required a W&B login. | Confirmed | `wandb.enabled: false` by default; `--wandb` or the config turns it on. | None. |
| T12 | `torch.cuda.amp.autocast()` / `GradScaler()` unconditional. | Confirmed | `torch.autocast(device_type=...)` and `GradScaler(enabled=amp and cuda)`; the loop runs on CPU (smoke test). | None on GPU. |
| T13 | Two `wandb.log` calls per epoch, so the W&B "Step" axis counts 2x epochs (the charts in the report run to ~90 and ~101 steps for ~45 and ~52 epochs). | Confirmed | One log call per epoch with `step=epoch`. | Affects only how charts read. |
| T14 | RandAugment magnitude: code `magnitude=1`, comment "Magnitude 0.5", W&B report "0.5" (2021) / "1" (2019). | Discrepancy, intent unknown | Config `randaugment_magnitude: 1` (what the code did), with a note. | None unless changed. |
| T15 | Eval geometry: images were resized directly to 224x224 (no centre crop) in both train and val. | Preserved | Kept as-is so that a rerun stays comparable in that respect. | None. |

## BioCLIP evaluation notebooks (-> `src/biodiv/clip_eval.py`, `encoders.py`, `species_data.py`, `prompts.py`; `scripts/eval_bioclip.py`; two notebooks)

| # | Finding in the 2024 notebooks | Status | What the new code does | Effect |
|---|---|---|---|---|
| C1 | `BioClip-INAT21-Fixed (2).ipynb`: `#label_emb /= label_emb.norm(dim=-1, keepdim=True)` is commented out for both checkpoints, while image embeddings are normalised. The argmax was therefore over cosine x ‖text‖, biased toward prompts with large text-embedding norms. (The older iNat 2019 and Rare Species notebooks did normalise both.) | Confirmed | `clip_eval.encode_prompts` and `encode_images` both L2-normalise; `cosine_scores` is a plain dot product of unit vectors. Tested with deliberately mis-scaled vectors. | **[changes results]** for B2 (0.6398) and B3 (0.7195); a rerun measures cosine similarity as in the BioCLIP paper. |
| C2 | Same notebook: the second checkpoint was created as `model, preprocess_train, preprocess_val = ...` but images were encoded with `preprocess` from the first checkpoint. | Confirmed | `OpenClipEncoder` keeps `preprocess_val` of the checkpoint it loaded; evaluation always uses `encoder.preprocess`. | **[may change results]** for B3; both are ViT-B/16 CLIP models and likely share the same preprocessing, but this was not verified. |
| C3 | Prediction index == dataset category id was assumed (`labels` built by iterating `categories` in file order; `image_labels` holds raw `category_id`). True for iNat 2019 and 2021 but never checked, and `if a not in labels` de-duplication would silently shift indices if two categories produced identical text. | Confirmed | `SpeciesTable.from_inat_categories` sorts by id and keeps `category_id -> species_id` explicitly; annotations are mapped through it. Tested with non-contiguous, unsorted ids. | No numeric effect for the real data. |
| C4 | Rare Species common names: 398 unique strings for 400 species; the label list was the unique common names, merging the two collision pairs. The taxonomic notebooks had 400 labels. | Confirmed (the notebook itself notes the 398) | Species identity is always the 400 scientific names; prompts may repeat. Identical prompts are encoded once (bit-identical embeddings, exact ties) and `tie_policy` is explicit: `first` (argmax, one species of each pair can never win) and `any` (true species among the tied maxima; equals the historical lenient scoring). Both are always reported, with the duplicate groups. Tested. | **[changes results]** for B4: a rerun is a 400-way task; `top1_accuracy_any` is the number comparable to the historical 0.2944, `top1_accuracy_first` is the strict one. |
| C5 | Rare Species notebooks built label lists with `range(len(json_reloaded['train']) - 2)`; no explanation. The subsequent `labels.index(...)` over all 11,983 rows did not raise, so the last two rows' species were already in the list and the `-2` had no effect. | Confirmed by reading the recorded outputs (400 and 398 labels; 11,983 image labels) | Not carried over; the species table is built from all rows. | None. |
| C6 | Hidden state: `BioClip-INAT21.ipynb` has a cell with a syntax error (`def load(js`) and uses `annotations` and `clip_labels` that were never defined in that notebook (they come from the `openclippy2` session); `rarespecies-*.ipynb` reference `label_emb` before it is defined (recorded `NameError`). | Confirmed | Every notebook and script defines what it uses, in order; `scripts/eval_bioclip.py` is a single entry point. Notebooks were executed from a fresh kernel (smoke mode). | None. |
| C7 | `model.to("cuda")`, `torch.cuda.empty_cache()`, `torch.cuda.amp.autocast()` unconditionally; fails on CPU. | Confirmed | Device auto-selected; autocast enabled only on CUDA. Everything runs on CPU. | None on GPU. |
| C8 | Image/label pairing: in the iNat21 notebook `image_paths` was appended for every image but `image_labels` only when an annotation existed, with only a length assertion afterwards; in all notebooks a single unreadable image would raise inside the batch loop and abort the run. | Confirmed (no misalignment occurred in the recorded runs: 100,000 of 100,000) | `ImageRecords` returns `(tensor, label, index)` so labels ride with their images through the DataLoader; unreadable images are skipped, counted and listed in the result instead of shifting anything. Tested by inserting a corrupt file mid-list. | None for the recorded runs. |
| C9 | Scores were `(100 * img @ txt.T).softmax(-1)` before argmax. | Harmless | Softmax removed (monotonic; argmax unchanged). Cosine similarities are returned. | None. |
| C10 | Checkpoints were loaded by name (`hf-hub:imageomics/bioclip`) with no revision. | Confirmed | `OpenClipEncoder(repo_id, revision=...)` pins a Hub commit via `snapshot_download` + open_clip's `local-dir:` loader; `configs/bioclip_eval.yaml` records the commits observed on 2026-10-23. | None; reproducibility. |
| C11 | Rare Species was exported to JSONL and reloaded from the Hugging Face cache paths; the `datasets` revision was not pinned. | Confirmed | `species_data.rare_species_from_hub(revision=...)` (pinned) or `rare_species_from_jsonl` for the old export format. | None. |

* `scripts/train_hiera.py` and `scripts/eval_bioclip.py` were smoke-tested on synthetic fixtures.
